= 令牌
:description: 32 位令牌的字段、有效门控，以及尚未完成的分发和编码。
:navtitle: 令牌

令牌是把一笔 8 位数据附上来源和类型，并用 `valid` 决定整字是否可见。生成器没有时钟。分发和编码还停留在占位。

== 字段

`st_token_generator` 把四段 8 位输入拼成 32 位，每一位都和 `valid` 相与：

[cols="1,1,2",options="header"]
|===
|位 |端口 |含义由端口名给出

|[7:0]
|`data_in`
|数据

|[15:8]
|`type_in`
|类型

|[23:16]
|`source_id`
|来源编号

|[31:24]
|`flags`
|标志
|===

`valid` 为低时，32 位输出全为 0。为高时，输出等于四段输入按上面的顺序拼接。这里的“类型”和 `st_memo_register` 里的 `memo_type` 没有在源码中接到一起。存储类型 `8'b00000010` 与 `8'b00000100` 只出现在存储通路。

== 一对四

`st_1_to_4_router` 有一个 32 位输入和四个 32 位输出。四个输出目前都连续赋值成同一个 `token_in`，`rst` 没有使用。它会把同一枚令牌复制四份，还不会按目的地选择其中一路。

== 编码器

`st_2_encoder` 的注释标明 WIP。它把 `req` 送进一只使能恒为 1 的锁存，`grant_fst` 等于锁存输出，`grant_sec` 等于其反相。使能恒为 1 时锁存是透明的，所以在 `req` 稳定之后，两路 grant 就是 `req` 和 `~req`。它还没有和第二级请求、应答接成仲裁。
